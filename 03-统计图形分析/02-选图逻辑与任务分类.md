# 02｜按分析目的选统计图：选图逻辑与误判边界

> 此文是**从统计解释目的出发的分析建议**，不声称 RAWGraphs 官方只有这些分类。实际可用图形见 [03-32种内置统计图形速查](03-32种内置统计图形速查.md)，以 App 注册表为核查依据。

## 0. 先问三个问题，而不是先看图形酷不酷

1. **最小观察单位**是什么？一人、一笔订单、一个国家的一年、一个节点还是一条连接？
2. **要回答什么问题**：谁多谁少、总体占比、随顺序变化、分布有多散、两变量有无关系、流向哪里、从属关系如何？
3. **读者需要读出什么精度**：准确比较数值、辨认趋势、找异常、看结构还是感受规模？

## 1. 统计目的 → 图形选择矩阵

| 主要目的 | 首选候选 | 数据最低结构 | 主要读取方式 | 易错点 |
|---|---|---|---|---|
| **比较绝对大小** | Bar chart、Multi-set bar、Slope chart（两期） | 类别 + 数量，或对象 + 两个状态 | 共同基线上的长度/位置 | 用面积代替长度、截断柱状图零基线 |
| **比较整体构成/比例** | Stacked bar、Treemap、Sunburst、Pie chart | 类别 + 可加总数量；层级图需层级列 | 比例、面积或环扇面积 | 总量口径不同、重复计数、类别过多 |
| **展示变化轨迹** | Line chart、Bump chart、Streamgraph、Horizon graph | 有序位置（数值/日期） + 指标；可加系列 | 位置和起伏、名次、堆积面积 | 顺序错乱、不同单位混在同图 |
| **展示分布形态** | Beeswarm、Boxplot、Violin plot | 每个观测记录有一个数值；可加组别 | 点密度、四分位、分布轮廓 | 把箱体当总量、忽略样本量 |
| **分析两个变量关系** | Bubble chart、Hexagonal binning、Contour plot、Voronoi diagram | 每行 x 与 y | 坐标散点、点密度、区域边界 | 相关误认为因果、过度拟合空间结构 |
| **同时比较多项指标** | Radar chart、Parallel coordinates、Matrix plot | 对象 + 多个数值列，或行列分类交叉表 | 多轴轮廓、平行轴的交叉、矩阵颜色 | 雷达不同轴单位不统一、过多曲线遮挡 |
| **分析层级/包含关系** | Treemap、Circle packing、Sunburst、Dendrogram、Circular dendrogram、Voronoi treemap | 多级分类列；可加数值权重 | 上下级、嵌套区域、树分叉 | 将树形结构误读成时间流程 |
| **展示对象之间连接** | Arc diagram、Chord diagram、Sankey diagram | source + target；可加权重 | 谁连接谁、流量多大 | 桑基流量单位不一、箭头方向未标 |
| **展示多阶段类别转换** | Alluvial diagram | 至少两列阶段类别；可加权重 | 类别之间的带状连接 | 把无时间顺序的“阶段”硬说成时间 |
| **展示区间/日程** | Gantt chart | 起始时间 + 结束时间；可加组别 | 区间起止与重叠 | 只提供开始时间、用柱长代表任务价值 |
| **展示聚类/几何包络** | Convex hull | x + y；可加组别 | 同组点的边界范围 | 把外包轮廓误认为概率范围 |
| **展示周期日历分布** | Calendar heatmap | 通常为日期 + 指标（以该独立依赖的版本为准） | 日历单元的颜色/强度 | 周起始日与缺失日的处理 |

### 名词解释

- **绝对大小**：10 人与 20 人。
- **整体构成**：同一个 100 人总体中甲占 30%、乙占 70%。
- **分布**：一组人每人的工资是如何散布，不只是平均工资。
- **关系**：A 值增大时 B 是否也增大，不一定存在因果。
- **流向**：从哪个来源到哪个目标、数量如何分配。
- **层级**：整体—子类—明细之间的包含或父子关系。

## 2. 看数值，选视觉编码

| 编码 | 统计读数质量（一般规律） | 优先场景 |
|---|---|---|
| 共同坐标轴的位置 | 通常最容易比较精确差异 | 点图、折线、散点 |
| 共零基线的长度 | 易比较数量大小 | 柱状图 |
| 面积 | 适合看部分—整体的规模结构，精准比较较难 | 矩形树图、气泡图 |
| 线宽/带宽 | 适合看连接或流量的量级 | 桑基图、弦图 |
| 色相 | 最适合区分类别，不适合暗示大多少 | 类别颜色、分组 |
| 明度/连续色阶 | 适合编码有序量级或密度，但需要图例 | 矩阵、日历热力图 |
| 形状/线型 | 适合区分对象类型和辅助检索 | 图标、虚实线、节点形状 |

注意：在图表本体中“尺寸”可能是长、宽、面积、半径或点的直径，**不能只看形状就假定它按数值线性映射**。看图例和具体 `render.js`。

## 3. 几个最容易混淆的图

### Treemap vs Bar chart
共同点：都可表达各类别大小。区别：Bar 用同基线的长度比较；Treemap 用矩形面积表达嵌套关系和部分—整体。若要精准比较 9 类数值，柱图更直观；若要同时读“部门—团队—成员”及总量构成，Treemap 更合适。

### Boxplot vs Violin plot
共同点：都以原始数值样本为输入。区别：箱线图突出中位数、四分位和须线；小提琴图突出平滑的密度轮廓。若样本量少，核密度的平滑形状可能不稳定，建议附样本量或原始点。

### Alluvial vs Sankey
共同点：都有带宽与连接。区别：[Alluvial](https://github.com/rawgraphs/rawgraphs-charts/tree/master/src/alluvialdiagram) 的源码将**至少两个分类字段**映射为一系列相邻列之间的关系；[Sankey](https://github.com/rawgraphs/rawgraphs-charts/tree/master/src/sankeydiagram) 接收**source、target** 连接边。前者常用于多阶段同一批记录的类别转变，后者可用于具有方向的连接或能量流。并非所有 Alluvial 的阶段都指时间。

### Line vs Bump
Line 画指标变化；Bump 重点看对象之间的名次或相对名次变化。若本意是展示数值绝对变化，别因为排名线更绚丽就选 Bump。

### Radar vs Parallel coordinates
Radar 适合极少数对象、同尺度的多个指标的轮廓呈现；Parallel coordinates 适合多个对象的多变量模式探索。两者在轴尺度和方向不统一时都会放大误读风险。

### Matrix plot vs Heatmap
Matrix plot（源代码名称）使用两类轴交叉的单元，可用颜色或面积编码值；热力图是广义视觉形式，不是一定有独立“Heatmap”图名。不要把图表英文名凭印象替换成 RAWGraphs 中不存在的专有分类。

## 4. 与五大数据架构逻辑的关系（**可能搭配**，不是等号）

| 数据架构中的主要关系 | 常见可借用的图形手段 | 需要额外判断什么 |
|---|---|---|
| **编年型**：单向有序链 | Line、Gantt、Slope、Bump、按序柱图 | “顺序”是否是核心结构？时间轴本身不是全部判断依据 |
| **层级型**：父子包含/分支 | Treemap、Sunburst、Dendrogram、Circle packing | 节点是否真的具有父子/包含关系 |
| **编目型**：主序列/索引与分组内容结合 | 分组柱图、矩阵、Alluvial 等作为局部模块 | **按本课程定义**，整体需同时体现主干编年序列与层级内容；不是看到分类就叫编目 |
| **字母表型**：独立条目、无固定先后 | 排序点图、平行比较柱图、词项矩阵等 | 每条是否可单独查阅？这里沿用课程约定，字母并非唯一形式 |
| **地理图型**：位置、邻接与空间分布 | 地图叠加统计符号、点/色阶、空间矩阵等 | 地点是否在空间位置关系中真正发挥组织作用；RAWGraphs 常见图未必提供底图 |

一个信息图形可以把多个统计图组合使用。**统计图类型只告诉我们数据怎样算、怎样编码；五大逻辑回答整张图为什么这样组织；17 种常用信息图形回答呈现形式和叙事形态。**

## 5. 选图核查清单

- [ ] 记录单位已统一，重复记录是否去重已决定；
- [ ] 分子、分母、单位、缺失值有定义；
- [ ] 图表接受的数据类型和字段数量满足源码限制；
- [ ] 对应的视觉变量表达的是数量、占比、类别还是关联；
- [ ] 基线、尺度、聚合方法、图例没有让读者误读；
- [ ] 读者能用一句话准确描述图形要回答的问题。
