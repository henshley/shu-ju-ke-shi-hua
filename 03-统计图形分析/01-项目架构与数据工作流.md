# 01｜RAWGraphs 项目架构与数据工作流

> 源码核查：2026-11-23。主项目 [rawgraphs-app](https://github.com/rawgraphs/rawgraphs-app) 的 `master` 分支；配套 [rawgraphs-core](https://github.com/rawgraphs/rawgraphs-core)、[rawgraphs-charts](https://github.com/rawgraphs/rawgraphs-charts)。以下凡“源码事实”均给出路径，其他“研究解释”用于理解其含义。

## 1. 用一句话理解

RAWGraphs 是把**二维表格（Excel / CSV / TSV / JSON 等）中的列**分配给**图表的视觉变量**，经过分类、聚合和布局计算，生成可继续编辑的统计可视化的开源工具。它的目标是连接电子表格与 Illustrator、Inkscape 等矢量编辑工具。

不是“导入图片并美化”；也不是“自动根据故事生成整张海报”。使用者仍需决定：研究问题、数据口径、选什么图、怎样解释结果。

参考：[项目 README](https://github.com/rawgraphs/rawgraphs-app/blob/master/README.md)。

## 2. 三个代码仓库分别做什么

| 层 | 仓库 | 在实际制图中的作用 | 可核对文件 |
|---|---|---|---|
| App（界面层） | [rawgraphs-app](https://github.com/rawgraphs/rawgraphs-app) | 加载数据、选择图表、拖动字段、设置样式、预览和下载。 | [src/App.js](https://github.com/rawgraphs/rawgraphs-app/blob/master/src/App.js)、[src/charts.js](https://github.com/rawgraphs/rawgraphs-app/blob/master/src/charts.js) |
| Core（数据与图形接口层） | [rawgraphs-core](https://github.com/rawgraphs/rawgraphs-core) | 识别与解析列类型、验证维度映射、准备聚合配置、调用图形绘制、项目序列化。 | [src/dataset.js](https://github.com/rawgraphs/rawgraphs-core/blob/master/src/dataset.js)、[src/mapping.js](https://github.com/rawgraphs/rawgraphs-core/blob/master/src/mapping.js)、[src/rawGraphs.js](https://github.com/rawgraphs/rawgraphs-core/blob/master/src/rawGraphs.js) |
| Charts（图形实现层） | [rawgraphs-charts](https://github.com/rawgraphs/rawgraphs-charts) | 定义每种图表接受的字段（dimensions）、把表格转为绘图数据（mapping）并计算布局、SVG 图形。 | [src/index.js](https://github.com/rawgraphs/rawgraphs-charts/blob/master/src/index.js)、各图形子目录 |

此外，App 通过独立包 `@rawgraphs/rawgraphs-calendar-heatmap` 注册日历热力图，支持自定义图形动态导入。内置图形数量与外部插件数量必须分开统计。

## 3. 从数据到图片的完整链路

```text
Excel/CSV/JSON/粘贴文本/URL/SPARQL
       ↓
DataLoader：读取、解析、确认字段类型
       ↓
DataGrid：检查“每行是什么、每列是什么”
       ↓
ChartSelector：选择图形
       ↓
DataMapping：字段 → 图形维度（拖拽）
       ↓
Core：校验必填字段、类型与多字段约束
       ↓
Charts / mapping.js：分组、计数、求和等
       ↓
Charts / render.js：布局计算 + 视觉编码
       ↓
ChartPreview：显示 SVG 等可视化
       ↓
Exporter：.svg / .png / .jpg / .rawgraphs
       ↓
矢量编辑器：再做标题、注释、配色、叙事版式
```

App 的 [DataLoader.js](https://github.com/rawgraphs/rawgraphs-app/blob/master/src/components/DataLoader/DataLoader.js) 列出粘贴、上传、示例数据、SPARQL 查询与 URL 加载；[DataMapping.js](https://github.com/rawgraphs/rawgraphs-app/blob/master/src/components/DataMapping/DataMapping.js) 负责把列放进图形变量；[ChartPreview.js](https://github.com/rawgraphs/rawgraphs-app/blob/master/src/components/ChartPreview/ChartPreview.js) 会提示缺少必填字段、字段类型不匹配等错误；[Exporter.js](https://github.com/rawgraphs/rawgraphs-app/blob/master/src/components/Exporter/Exporter.js) 明确列出四种导出格式。

## 4. 源码里的四种核心概念

### 4.1 行记录 record

表格的一行是一个观测单位。一行可以代表“一个国家某一年的 GDP”“一部电影”“一个人”“一条来源→目标连接”。如果混用记录单位，会导致错误汇总。

### 4.2 字段 column / data type

字段是表头。Core 会尝试识别 `number`、`string`、`date` 等类型。数值型可以用于大小、求和或分位数；字符型常用于类别、标签；日期型可用于时序位置和区间。**看着像数字的编号仍应视作类别键**，如 `001`、身份证后四位、商品编码，避免丢失前导零。

### 4.3 图形维度 dimension

图形的 `dimensions.js` 不是指“数据有几维”，而是“这个图要往哪些槽位放字段”。例如柱状图：
- `Bars`：必填的类别，决定一根柱是谁；
- `Size`：可选数值；不填时按记录数计数；
- `Color`：可选颜色变量；
- `Series`：可选系列分组。

见 [barchart/dimensions.js](https://github.com/rawgraphs/rawgraphs-charts/blob/master/src/barchart/dimensions.js) 和 [mapping.js](https://github.com/rawgraphs/rawgraphs-charts/blob/master/src/barchart/mapping.js)。

### 4.4 分组聚合 aggregation / layout

把相同类别的原始行归在一起是“分组”；把多行求和/计数是“聚合”；根据计算结果画位置、面积、带宽等是“布局编码”。三者各有含义。**图上面积大，不代表源码自动认为它重要；重要性是读者的解读，数值量级由编码规则确定。**

## 5. 图形定义的代码结构（用柱状图举例）

```text
rawgraphs-charts/src/barchart/
├── index.js        入口
├── barchart.js     组装图形定义
├── metadata.js     名称、说明、分类、代码和教程链接
├── dimensions.js   必填/可选字段，支持的类型、聚合默认值
├── mapping.js      数据如何分组、计数和汇总
├── visualOptions.js视觉可调参数
├── render.js       实际的图形渲染
└── *.svg           选择器图标和缩略图
```

源代码说明：柱形图的 `size` 在映射数值列后使用 `sum` 作为默认聚合；不映射则回退为同一分类内的记录数 `v.length`。因此“同样的柱形图”可能画的是**人数**、**销售额**，也可能画的是**记录条数**，必须在标题或图例写明统计口径。

## 6. 数据和隐私边界

项目 [README](https://github.com/rawgraphs/rawgraphs-app/blob/master/README.md) 表示导入数据主要在浏览器侧处理，不进行服务器端数据存储。但实际使用 URL、外部 API、SPARQL、自定义插件、页面分析服务时，仍应分别核对数据请求和浏览器环境，不应把 README 的说明扩展成“任何使用场景都不会向外发送信息”。

## 7. 如何用于信息图形设计

RAWGraphs 擅长：把数据关系计算成可编辑的统计图；适合再使用 Illustrator、Inkscape、Figma 等排版工具完善视觉语言。

RAWGraphs 不代替：确定信息架构、建立故事主线、写数据来源、判断误导性比例尺、确定整张图的读者和意义。

**建议流程**：先选数据问题 → 确认表结构 → 选统计图 → 检查映射和口径 → 导出 SVG → 设计叙事顺序 → 检查图例和结论。
