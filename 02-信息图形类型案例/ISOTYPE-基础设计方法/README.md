# ISOTYPE｜基础视觉设计方法（非信息图形类型）

> **分类声明：本专题不是第 18 种信息图形，也不是五大数据架构逻辑之一。** 它是跨图形类型使用的**信息视觉转译与符号设计方法**。本文件夹作为 `02-信息图形类型案例` 下的独立专题标签，与 `01–17` 类型文件夹并列，但**不参与类型编号及统计**。

## 1. ISOTYPE 是什么？

**ISOTYPE**（International System of Typographic Picture Education，国际图画文字教育体系）是以标准化图形符号组织、解释和传播信息与统计资料的一套视觉方法，起源于奥托·纽拉特（Otto Neurath）及其团队的图画统计实践。

关键不在于“画小人”，而在于**用一套可理解、可重复、单位一致的符号规则，将抽象数据转译为能被阅读和比较的视觉语言**。

参考：[Isotype Revisited — Introduction](https://isotyperevisited.org/2012/08/introduction.php)、[Stanford Encyclopedia of Philosophy — Visual Education](https://plato.stanford.edu/entries/neurath/visual-education.html)。

## 2. 核心设计原则

1. **符号标准化**：一个概念尽量使用形式稳定、易识别的图形符号；同一图中的同义对象保持一致。
2. **数量通过重复表达**：用于数量编码时，一个同尺寸图标对应固定数量，数值增大原则上**增加图标个数，而不是放大单个图标**。
3. **单位与图例明确**：必须说明“一个符号代表多少”，并统一比较的基准；无法整除时应采用预先说明的规则，不可随意画半个图标冒充精确数值。
4. **简化与平面化**：优先使用易识别的二维轮廓和形状，避免透视、装饰细节干扰信息识别。
5. **排布形成阅读秩序**：重复、对齐、分组、间距、标签和颜色共同帮助读者阅读和比较；颜色首先承担区分类别或辅助理解的职责。
6. **信息转译而非堆图标**：选择什么符号、怎样定义量化单位、如何去除无关细节，都是“从原始信息到可视表达”的设计决策。

**示意（虚构教学数据）：**

```text
每个 ■ = 10 人

A 组：■■■     = 30 人
B 组：■■■■■   = 50 人
```

这是说明“固定单位符号 + 重复计数”的抽象示意，并非 ISOTYPE 的历史原图。实际设计中可把 ■ 替换为统一的具象图画符号。

## 3. 为什么不是一种信息图形类型？

- **信息图形类型**描述成品的组织与呈现形式（时间轴、比较、层级、列表、混合等）。
- **ISOTYPE**描述可被这些形式采用的符号语言、数据转译与编码方法。
- 同一幅“比较型信息图”可以使用 ISOTYPE 重复图标，也可以使用柱形图；同一套 ISOTYPE 图标也能用于编目/对比/地理等不同组织结构。
- **出现人物剪影、小图标，不等于使用了 ISOTYPE 方法**：应检查符号是否具有稳定含义、重复是否承载明确数量、单位和比较口径是否一致。
- 因此 ISOTYPE 不能替代五大数据逻辑判断，也不能直接替代统计图类型判断。

## 4. 将来保存案例时怎样分析？

本专题用于收录具有 ISOTYPE 特征的设计方法案例。以后每张案例继续采用“案例1图片 / 案例1分析.md”的配对方式；分析应优先记录：

| 分析字段 | 主要看什么 |
|---|---|
| 概念与主体 | 讲什么信息，为什么需要图画语言 |
| 基本数据单位 | 一个图标代表 1 个、10 个还是 1 万个？单位一致吗 |
| 图形符号系统 | 图标轮廓、简化程度、等尺寸、重复规则 |
| 数量编码 | 重复个数、整除与取整、类别之间能否直接比较 |
| 编排规则 | 阅读路径、对齐/成组/间距/标签/图例 |
| 色彩规则 | 类别区分、重点提示、与数量编码是否冲突 |
| 统计及叙事衔接 | 是否借用柱图、点阵、地图等图形形式；如何引导读者理解 |
| 适用边界 | 数据量过大、精度需求高或符号难辨时，何种编码更合适 |

可将 **A 基本数据逻辑、B 统计计算、C 视觉编码、D 信息架构、E 视觉叙事** 作为更完整的案例结构，但要注意：**ISOTYPE 本身属于视觉设计/编码的方法层，不是 A 的第五类或 02 的第十八类**。
