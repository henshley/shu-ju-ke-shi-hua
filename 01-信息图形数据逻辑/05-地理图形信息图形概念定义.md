# 地理图形信息图形概念定义

## A 基本的数据逻辑

空间位置、方位、邻接、路线或覆盖范围是主要关系。对象可对应点、线、区域，也可对应沿地点变化的指标。帝都地图 的地点虽然来自虚构世界，街区相对位置和道路连接仍决定了它的读法。

**判断方法**　调换两个地点或挪动一条线，观察空间结论是否会变。课件也收录了 世界山脉与河流比较图。它属于地理主题，但主图可以主要按高度和长度来读。分析此类作品时分别记录题材和布局中的主关系。

**分类边界：** 地理图型的核心是地点的**空间位置、邻接、距离、方向或区域形状**参与表达结论；仅在数据表中含有国家、城市、地址字段，不足以判为地理图型。如果国家只是可重排的同构比较对象，整体可能是**字母表型**；如果一张地图仅作背景装饰，也不能凭题材直接判为地理图型。17种表现类型中的“地标型”也不等同于五大数据逻辑中的“地理图型”。

## B 统计图形与计算方式

| 表达任务 | 图形与统计方式 |
| --- | --- |
| 找地点、街区和路径 | 用定位地图或线路地图。先将地点和路线对应到底图，按图例区分不同设施、道路与区域。 |
| 看各区指标怎样分布 | 用分级设色地图。比较风险或占比时可按人口、面积等适当分母标准化，再按明示的阈值分级。 |
| 看各地总量或流向 | 用比例符号地图或流向图。制图时让符号面积或线宽对应明确的量，并在图例中交代单位。 |
| 看地貌和河道变化 | 用等高线、高程剖面或多期河道叠图。两期比较使用统一底图与空间范围。 |

密西西比河历史河道图 可沿底图读取不同河道范围。原图的填色用于辨认图例分组，比较面积前要确认比例尺和面积计算口径。

## C 视觉编码

点定位地点，线表达河道、路线和边界，面表达地块和覆盖范围。色相可区分地物或历史河道，顺序色阶可表示量级。符号配合地名和图例解释地点类型。立体高程应与可读的高度基准对应，优先保证地图的方位与地点标记清楚。整体范围与局部细节可用主图和插图衔接。

## D 数据与信息架构

最小记录包括 `地点或区域 ID、名称、空间几何、属性或指标`。定量专题可补充 `日期、单位、分母、来源`。历史地图还需记录时期、底图范围和图例类别。信息层可包括底图、专题层、地名标注、图例与补充图，数据有尺度时附比例尺和方位说明。

## E 视觉叙事架构

先让读者认清地图的范围，再由图例定位主要区域、路径和重点标注。河道案例可以从现有底图进入，沿河谷辨认多条历史河道的叠合，并通过图例理解它们所处的组别。帝都地图 则支持从中心城区向外按道路寻找相邻街区。


## 案例补充｜2024 年美国大选多图联动（地理图型主导的混合型信息图形）

- **基本逻辑**：以州为公共数据索引，绑定胜选党派、选举人票、领先幅度、投票率以及历史投票次数等属性；同一地理单元在多幅图中重复出现，实现跨视图对照。
- **判断关键**：州域领先差和投票率地图中的位置、邻接与区域边界直接影响空间结论，因此这部分具有地理图型核心特征。若改成按名称排列的条形图，仍可比较数值，却无法保留“哪些地区连片、相邻地区有何差异”的空间信息。
- **常用统计方式**：州级分类汇总、频数计数、得票率/投票率计算、两党得票率百分点差、分级设色、多年份同口径对照。胜选选举人票的方格计数、议会席位点阵与全国条形图可以与地理地图并置，但**方格网格图并非按真实土地面积比例绘制**。
- **视觉编码**：州的位置与行政边界表达空间关系；党派用不同色相，领先幅度用同色系深浅，数量用长度或重复单元个数；投票率另用顺序色阶表示。跨图统一党派色义。
- **数据结构**：建议最小表头为 `州 ID｜州名｜年份｜指标类别｜数值｜单位｜党派｜地理几何`，另设单独的全国汇总、议席统计和历史频次数据表，并注明各指标的统计口径。
- **信息架构与叙事**：先展示全国胜选结果，再展示各州选举人与领先差的空间格局，以席位、投票率、历届胜选次数和跨年度比较补充解释；属于“结论先行—空间展开—辅助比较”的叙事。
- **边界判断**：该案例在**常用信息图形种类**上是混合型，不能把“混合型”当成五大数据逻辑之一；右侧按州并列的历史条形图属于局部非地理组织，具有字母表型的独立单元特征。整版“地理图型主导”不等于每个模块都必须是地图。

## 案例补充｜圣米格尔德阿连德城市导览地图（地理图型／地标型）

- **五大数据架构逻辑：地理图型。** 本图围绕二维空间的地点位置、街区边界、道路连通、方位、邻近、包含关系组织信息；交换 GUADALUPE 与 SAN ANTONIO 等街区的位置会破坏地理结论。其主干是空间约束，而不是编年顺序、父子层级或任意可重排的独立单元。
- **17种常用信息图形：地标型（Location Infographics）。** 地图提供街区定位、地点识别、道路导览和设施检索；建筑照片、景点清单、服务图标都是为地理导航服务的辅助层。元素多样不意味着一定要归为混合型。
- **A｜通用数据规律：** 多方向、非线性、空间位置不可随意置换；空间对象通常分为点（地标／设施）、线（道路／水系）、面（街区／绿地）；对象既能独立查找，又可通过邻接、相交、连通、归属关系关联。
- **B｜统计图形与计算：** 借用定位地图、分类区域地图、点位符号地图和道路网络图的结构。处理可涉及坐标映射、空间分类、道路拓扑、点位—区域关联、几何简化；**本图并没有用明确数值图例表达频数、密度或比例**。RAWGraphs 的散点图只可类比双坐标定位原理，不能直接代替地理底图和道路／多边形几何。
- **C｜视觉编码：** 位置编码地点；白色道路与蓝绿水系通过线形表现连接；暖红面为主要建成街区，绿色面为自然与绿地，紫色圆点强调部分重要节点；图标表达设施类别，照片和文字表达地点属性。照片大小、线宽、色彩深浅、网点纹理未构成明确的定量映射。
- **D｜数据／信息架构：** 统一空间参照 → 区域表（区域 ID、名称、类别、面几何）＋路网表（道路 ID、线几何、节点连接）＋地点表（地点 ID、坐标、类别、所属区域） → 标签、照片、图标及图例。复杂线面几何可用 GeoJSON／GIS 存储，Excel 主要承担属性表。
- **E｜视觉叙事：** 先识别城市整体范围，再按街区、地标、道路与外部出口定位，最后通过底部清单和图例检索细节；读者可从任意地点进入，属于**空间导览型、非线性、自由探索叙事**。
- **判断边界：** “地标型”是17种表现形式中的一类，“地理图型”是五大底层数据架构逻辑之一；二者常共同出现，但不能互相当作同一分类层级。地名出现本身并不足以证明地理图型，必须检验空间关系是否承载核心信息。

## 案例补充｜MOMO Coffee · Colonia Roma 艺术路线导览图（地理图型／地标型）

- **五大数据架构逻辑：地理图型。** 以 Roma 街区的街道网络与15个地点的空间位置为主干，核心关系是位置、方位、邻近、道路连接及地点与街区的空间归属。地图标记的位置并非可以任意重排的列表坐标。
- **17种常用信息图形：地标型（Location Infographics）。** 主图为街道导览地图，橙红色圆形编号对应15个场所；下方三栏地点名称和左侧 Google Maps 二维码均服务于“定位—识别—实地导航”的任务。
- **A｜数据规律：** 空间位置约束、非线性、多入口、地点独立可检索、地图点位与名称清单一一关联。地点上的1—15数字只是索引ID，**不构成必须依次进行的时间序列或路线步骤**。
- **B｜统计图形与计算：** 主要借鉴定位地图（Location Map）、点位符号地图（Point/Symbol Map）、道路网络表示与交叉索引；可通过坐标映射、地点ID匹配、空间相邻与简单计数处理。**原图未展示比例、密度、均值、地点间实际距离等定量统计结果**。RAWGraphs Scatterplot 只能类比双坐标定位，不能直接替代地理底图。
- **C｜视觉编码：** 深蓝线条为路网与主要文字；橙红色圆形编号强调地点，橙红手绘插画强化场所主题与品牌调性；浅米白底保留空间留白。地图居中，下方三栏目录做文本反查，左侧二维码承担线下导览延伸。**图标大小、圆点大小、星形装饰及道路宽度没有明确数值含义**。
- **D｜数据／信息架构：** 区域（地图参照）→ 道路／街道（线）→ 地点（点）→ 地点ID与属性（名称、类别）→ 目录/二维码。概念性地点表适合采用“地点ID｜名称｜经度｜纬度｜类别｜附注”；道路应另存道路名与线几何，地图还需地理参照。原图未附精确点位坐标，不能据示意图臆造。
- **E｜视觉叙事：** 品牌与路线主题 → 街区总览 → 地点探索 → 编号与三栏地点清单双向匹配 → 扫码使用 Google Maps。属于**自由探索式、非线性、空间导览叙事**，不是按1→15单向推进的时间线或流程图。
- **边界与判断方法：** “地点在哪里”比“地点按何顺序排列”更重要，便以地理图型为主；**编号列表只是检索机制**，不自动将整幅图变成编年型、层级型或编目型。地标型（视觉表现）与地理图型（基础数据架构）属于不同分类维度。
