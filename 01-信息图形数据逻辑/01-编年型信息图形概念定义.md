# 编年型信息图形概念定义

## A 基本的数据逻辑

以一条有方向的序列组织事件、阶段或状态变化。核心关系是「第几步、谁先谁后、哪些项目属于同一阶段」。课件第 3 页概括为单向、不可逆、顺序排列，数据维度以一条主要序列为主。这里的不可逆指先后关系由记录或规则确定。排版可以从下往上，也可以折返，读取方向可以改变，原本的先后关系仍须成立。并行事件可共用一个顺序位置，或并排放在各自的轨道上。

**判断方法**　交换两个节点以后，如果读者会误解事情的经过，说明顺序承担了结构功能。如果交换只影响条目好不好找，应继续检查排序是否只是索引。课件的 Gear Timeline 用连续曲线串起阶段，能沿路径辨认前后关系。

## B 统计图形与计算方式

| 需要回答的问题 | 图形与处理方式 |
| --- | --- |
| 发生了哪些事、顺序如何 | 用事件节点或分段轴。按顺序键排序，节点和说明一一对应。仅知道先后关系时，可用等距排列。 |
| 相隔多久、持续了多久 | 用等比例轴和区间条。位置由实际刻度确定，区间长度为结束值减开始值。 |
| 数值怎样随序列变化 | 用按期柱形图比较各期合计，用折线图显示同口径数值的变化。增减量为本期减上期，百分比增减还需同口径的非零基期。 |

包豪斯案例 显示年份节点和建筑注释。由图可读出先后，读取精确间隔前需要确认刻度。原图中未标单位的节点大小或图像面积按图文布局解读。

## C 视觉编码

点定位事件。线串联相邻节点，折返处保留连续性和方向提示。面承载阶段分区或已定义的区间。色彩区分阶段、支线或重点，图例维持一致。建筑轮廓等符号帮助识别事件对象。需精确比较数值时，优先让共用标尺上的位置或长度承担读数，立体效果用于说明形态时应保留可读的二维刻度。

## D 数据与信息架构

最小记录可以是 `事件 ID、顺序键、显示标签、主体、事件说明、来源`。区间事件补充起止值，并行序列补充轨道，同期事件共用顺序键且各有事件 ID。页面用一条主轴形成总览，按阶段组织节点，详情和图像从节点展开。

## E 视觉叙事架构

让读者先找到开端和读取方向，再沿主轴认识阶段的变化，最后通过注释查看里程碑为何重要。内容折返或环绕时，每次转换方向都要保有接续线索。案例既有 单人经历的曲线阶段，也有 报刊跨页中的连续折返。

## F 补充：与编目型和常用图形种类的边界

**五大数据逻辑看的是“先后关系”是否主导，不是图片、栏目或文字数量。** 顺序主干可以是时间、步骤或演变阶段；“编年型”不要求实际日期。

- **仅有有序阶段＋人物／照片／正文说明：** 照片和文字是事件节点的属性，仍归**编年型**，即使每个阶段的信息很丰富，也不能据此认定“层级型内容”。
- **有序阶段＋真正的父子分支结构：** 除了阶段顺序，还能辨认“阶段 ID → 下级类别或子项目 ID”，且下级项目的归属对理解有实质作用时，应按本仓库定义进一步判断为**编目型**（编年主干＋层级内容）。
- **按内容类别独立列出的补充资料：** 即便与时间轴同页，也不自动构成“每阶段下属内容”的层级；需审查它们是否真的挂接在有序阶段之下。
- **常用表现类型另行判断：** 时间轴型、编年图与编目混合型等属于17种视觉表现分类，不能仅依据名称决定五大数据架构归类；时间轴上有多张图片也不意味着它是编年图与编目混合型。

**案例提醒：**《萨尔瓦多·达利逝世25周年》的旧文档提到左侧生平与右侧作品栏目。是否构成**五大逻辑中的编目型**，须复核原图是否存在“主干阶段 → 具体子项目”的清晰从属关系；独立的作品目录本身不足以证明这一点。在完成原图复核前，此例不作为编目型的确定性判例。


## G 案例补充｜电磁学发展史时间轴（03-时间轴型·案例1）

**案例位置：** [02-时间轴型信息图形／案例1分析](../02-信息图形类型案例/03-时间轴型信息图形/案例1分析.md)

**两套分类：** 五大数据逻辑为**编年型**；17种常用图形类型为**时间轴型（Timeline Infographics）**。不得因为存在人物肖像、实验设备、公式和多段介绍，就误判为“编年图与编目混合型”。

### A 基本的数据逻辑

- **单向、不可逆、顺序排列：** 以18世纪→1820年→1860年代→1880年代→19世纪末至20世纪初→20世纪前中期串联发展阶段。
- **单一主排序键＋节点属性：** 时间（或阶段顺序）控制历史关系；人物、发现、理论、图片、文字是对应节点的附属字段。
- **非层级判断：** 能把事件旁的照片／正文移到一个普通属性列，不说明存在真实“阶段→子类别→子项目”父子结构。不能把文字与标题之间的**视觉层级**误判成数据层级。

### B 统计图形及处理方式

- **主要图形：** 事件时间轴（Event Timeline），属于有序信息组织，不是传统定量统计图。
- **处理：** 按年份排序（Sorting）、按年代／世纪分组（Grouping）、事件关联人物与成果（Mapping）、年代标签（Labeling）。
- **计算边界：** 原图时间节点位置不是按照年份差等比例映射；人物照片与设备图的大小不代表成果数量或研究重要性。不能擅自说采用了比例计算。
- **工具判断：** RAWGraphs 不必强行对应单个原生图形；只有具备实际起止时间与持续时间等字段时，才考虑借用甘特图／区间条的长度表达。

### C 视觉编码

| 视觉元素 | 可迁移规则 |
| --- | --- |
| 点 | 白色节点与端点定位历史事件及注释 |
| 线 | 细引导线对应事件与说明；电磁波、磁场线是主题符号，不是数据趋势线 |
| 面 | 黑白照片、矩形拼贴及橙色几何面形成图文模块 |
| 体与符号 | 磁铁、器材、公式展示专业主题，默认不编码数值 |
| 色彩 | 橙色突出年份／节点，黑白灰呈现历史感并维持统一 |
| 字体／版式 | 巨型主题字＋大号年份＋小号注释；自由拼贴，但确保历史顺序可追踪 |

### D 数据／信息架构

建议 Excel 列：`事件ID｜顺序键｜时间标签｜人物｜事件或成果｜文字说明｜图像来源`。**一行对应一个历史事件／阶段，一列对应其属性**；同期多事件可用多行和相同时间键表达，而不必创建虚假的父子节点。

### E 视觉叙事架构

**主题引入→早期探索→关键发现→理论建立→实验验证→技术应用与延伸**。大标题先吸引关注，橙色年份构成历史定位，人物与器材丰富节点说明。图文可以上下错位，但可读的时间标记要保证主序列不被误读。

**判断口诀：** 看主干是否必须有序，再看节点内是否确有**独立下级项目**；**仅有“时间轴＋说明＋照片”＝编年型数据逻辑＋时间轴型表现**，不能据素材多寡直接判编目型。

## G 补充：示意图型（How-to）的编年型步骤数据与流程图型边界

**新增案例**：[越南肉丸米粉 Bún mọc 的制作示意信息图](../02-信息图形类型案例/04-示意图型信息图形/案例1分析.md)。该例在五大数据逻辑中属于**编年型**，在17种常用信息图形类型中属于**04-示意图型（How-to Infographics）**。两套分类回答不同问题：**数据靠什么关系组织？** 与 **通过哪一种形式向读者解释？**

### 关键概念与判断依据

- **编年型不以出现“时间”二字为必要条件。** 以“操作顺序／阶段先后／事件历程”作为唯一主要顺序键，有明确先后关系，就可能是编年型；某个步骤可以有说明文字、图像、配料属性，不因此自动转为层级型或编目型。
- **“单向／不可逆”是对有序主干的结构描述。** 它指不能不加说明就把节点的既定先后次序颠倒，**不**表示真实操作过程里所有动作绝对不能同时进行。以菜谱为例，备汤和切配菜可能部分并行，应区分“海报编号顺序”与“真实因果依赖”。
- **示意图型 How-to 的识别重点**：教读者如何完成具体任务；把动作拆为操作步骤，用具象食材／器具／手势插画与短指令示范“怎么做”。
- **流程图型 Process 的识别重点**：节点之间的连接、流转、分支、合流或工序依赖本身是核心信息。**流程图可以是单一路径**，多线程是常见特征但不是绝对必要条件；因此不能用“有／没有分支”单独判断。
- **时间轴型的识别重点**：表现时间历程、里程碑及其发生先后，可能用日期和刻度，但不能因为某张图只有步骤编号就认定为时间轴型。
- **有编号≠必然是流程图；有插画≠必然是示意图。** 先看主要说明目的，再看图形中真正承载信息的元素。该米粉案例依靠操作图解教学，故优先示意图型；其编号与米粉曲线是有序阅读的视觉组织手段。
- **“编号＋内容说明”≠编目型。** 该例中每个编号后的动作、对象和配图是**步骤记录的字段**；底部食材名录是旁列辅助信息，并非五个步骤下实质的子类别／子项目，不能推出“编年主干＋层级内容”的编目关系。

### 与统计图形／视觉编码的对应

- **数据结构**：每行一个步骤，最小字段为 `step_id｜seq｜action｜object｜explanation｜visual_asset`；例图5个步骤，对应5行。食材图例可另表保存，但不替代主序列键。
- **统计处理**：步骤计数、按顺序键排序、阶段分段；原图没有可验证的量值轴、比例或定量关系。若画面使用弯曲长线连步骤，其线长与面积无明确量值映射时，**不得**解释为趋势线、桑基流量或真实时长。
- **视觉编码**：数字圆点标出步骤，连续米粉形态引导观看，食材／动作插画解释操作；颜色、透视和大幅成品碗建立阅读主次，而非统计量级。
- **视觉叙事**：主题导入→步骤拆解与图解示范→完成效果→辅助食材识别。视觉上可以先看到成品，再回到操作序号，**观看路径不改变底层编号次序**。

**新增的可迁移判断模式**：`有序动作（编年型数据）＋具象操作示范（How-to 表现）＋成果展示`。判断数据逻辑看先后关系是否为主干；判断常用类型看是“教人怎么做”，还是“说明流程节点如何流转”。
