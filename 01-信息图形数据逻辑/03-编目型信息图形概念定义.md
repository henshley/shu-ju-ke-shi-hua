# 编目型信息图形概念定义

> **五大数据架构逻辑中的“编目型”＝编年型主干＋层级型内容。** 本仓库采用此特定定义，不能把日常意义上的“目录、分类、条目清单”直接等同于编目型。

## A 基本的数据逻辑

**一条不可随意颠倒的有序主干，带出各阶段内部有明确上下级归属的内容结构。**

- **编年型主干（横向／纵向推进）**：阶段 A → B → C，顺序有实际意义，颠倒会改变发展、实施或演变关系；不必一定出现日期。
- **层级型内容（向下展开）**：某个阶段 → 下属类别／任务／子项目 → 各项属性或数据。阶段与下属内容的父子归属明确，同一阶段可以有多个关键数据。
- **二者共同构成结构**：不仅知道“先做什么、后做什么”，还要知道“每一步包括哪些真正独立的下级事项”。

**判断方法（两个条件须同时成立）：**

1. **顺序测试**：交换主干阶段的位置，是否会破坏原本的过程／发展逻辑？若否，不能认定有编年主干。
2. **归属测试**：能否明确列出“阶段 ID → 子类别／子项目 ID”的父子关系？移动一个子项目到另一阶段，是否会改变其信息归属？若只有年份旁的一张照片、一段说明，不足以认定层级结构。

**边界：** 单纯的分类列表、单一主题下的独立卡片、时间轴节点旁附人物照与文字，均不因“内容多”就自动成为编目型。标题和正文字号差异也不等于数据的层级关系。

## B 统计图形与计算方式

| 表达任务 | 可用图形／组织方式 | 数据处理与计算 |
| --- | --- | --- |
| 展示主干的不可逆顺序 | 时间轴、阶段轴、有向流程节点 | 按阶段序号或发生顺序排序；只有先后信息时可等距绘制 |
| 展示各阶段包含哪些子项 | 分支树、缩进层级、子项目分组卡片 | 按上级 ID 分组，建立阶段与子项目的一对多关系 |
| 比较阶段或子类别数量 | 分组条形图、堆叠条形图（有数值时） | 按阶段或类别计数／求和，前提是统计口径一致 |
| 表示各阶段持续时长 | 甘特图／区间条（有起止值时） | 时长＝结束值－开始值 |
| 显示层级中的部分占整体 | 矩形树图、旭日图（有可加总数值时） | 子项占比＝子项值÷所属上级总值；不能重复计数 |

**注意：** 编目型不要求一定有数量统计。顺序与归属首先是**数据关系**；人物、器材图片以及装饰形状大小不能在无标尺时被解释成统计数值。RAWGraphs 等制图工具提供的统计图形是可选表达手段，不决定五大数据逻辑的归类。

## C 视觉编码

- **点**：标记阶段节点、子项目节点；用位置区分主干和分支。
- **线**：实线／箭头连接先后阶段；分支线、引导线表示“上级 → 下级”的归属。两类关系应可区分。
- **面**：阶段色带、分组底板、卡片容器显示不同节点和子项所属区域。
- **体**：具象场景或立体插画可帮助解释内容，除非明确规定，否则体积不编码数量。
- **符号与图像**：阶段图标辨认主干任务，子项图标辨认具体内容；图像应对应其所属节点。
- **色彩**：主干使用连续、一致的强调规则；同一阶段下的子项沿用分组颜色，避免错认从属关系。
- **字体和版式**：主题 → 阶段 → 子类别／子项目 → 属性说明的字级清楚；阅读方向明确，子项靠近或连接其上级节点。

**核心编码：位置／箭头表示先后，分支／嵌套表示归属，字号与色彩辅助识别；视觉大小并不天然代表数据值。**

## D 数据／信息架构

**基本结构：总主题 → 有序阶段主干 → 各阶段的下级类别或项目 → 下级项目属性。**

推荐至少用两张数据表：

**表1：阶段主干表**（每个阶段一行）

| 阶段ID | 顺序键 | 阶段名称 | 说明 |
| --- | ---: | --- | --- |
| S1 | 1 | 阶段A | 第一阶段 |
| S2 | 2 | 阶段B | 第二阶段 |

**表2：层级内容表**（每个真正独立的下级内容一行）

| 子项ID | 上级阶段ID | 子项名称 | 指标／说明 |
| --- | --- | --- | --- |
| C1 | S1 | 子项目甲 | 属性1 |
| C2 | S1 | 子项目乙 | 属性2 |
| C3 | S2 | 子项目丙 | 属性3 |

若子项还包含下级事项，可增加 `上级子项ID`／`父节点ID`。阶段主干保存**顺序键**，内容表保存**父子归属键**，不能只靠版面上哪个标题更大来推断关系。

## E 视觉叙事架构

**总主题 → 沿不可逆主干逐阶段阅读 → 展开每阶段的下级内容 → 回到主干继续推进 → 全局总结。**

读者通常先回答“过程走到哪里”，再回答“这一阶段包含什么”。主干控制阅读的总体方向，下级信息允许在阶段内部进行分支阅读；不同阶段不能因为版面拼贴而失去衔接关系。

## 与相近类型的严格区别

| 情况 | 五大数据逻辑中的判断 |
| --- | --- |
| 有序历史节点＋人物照片／事件文字（仅为节点属性） | **编年型**，不因图文丰富而变成编目型 |
| 主题 → 分类 → 条目，分类之间没有不可逆先后 | **层级型**（确有父子结构时）；不能只因叫“目录”就判编目 |
| 多个独立对象共享同一字段，可任意重排，无父子关系 | **字母表型** |
| 有序阶段＋每阶段有明确的子类、子项目或分支归属 | **编目型** |
| 画面同时使用时间轴、照片、图标、文字等多种视觉元素 | 不足以直接判断数据逻辑；应先检查顺序和父子关系 |

**两套分类不可混淆：** “编目型”是五大数据架构逻辑之一；“时间轴型”“编年图与编目混合型”“混合型”等是17种**常用信息图形表现类型**。不能从图形的视觉名称直接倒推底层数据逻辑。
