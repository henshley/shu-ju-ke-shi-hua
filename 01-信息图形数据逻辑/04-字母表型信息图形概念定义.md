# 字母表型信息图形概念定义

> **本仓库五大数据逻辑中的“字母表型”＝一组彼此独立、平行、同构、没有强制先后或父子层级的记录。** 名称取自便于独立检索的编排思路，并**不要求实际按 A–Z 排序**。

## A 基本的数据逻辑

**最小单位是彼此独立的对象或条目。** 每个对象拥有同一组可比较的字段，既不依赖其他对象先发生，也不以其他对象为父节点。

- **独立**：一个单元被移走，不会破坏其他单元的含义。
- **平行**：不同单元地位相同，没有上级、下级、继承或包含关系。
- **同构**：各单元使用一致的记录模板，例如“国家｜指标｜数值”、或“关键词｜权重”。
- **无强制顺序、可重排**：可按名称、数值、类别或任意展示顺序浏览；改排版不改变对象之间的数据关系。

**判断方法：** 把信息表中的两个对象交换行次，再检查它们是否仍然各自成立、字段是否相同、是否不存在关键父子依赖。若是，则具有字母表型的核心特征。

**传统 A–Z 字母索引和符号表**是这种独立单元的一种常见索引表达：字符顺序是查找工具，而不是事件间不可逆的发生顺序。字母表型也可以画成并列的小卡片、同尺度比较图、符号阵列或词云。

**重要边界：** 仅仅能拆成若干栏目，还不足以判断为字母表型。若栏目内部存在真实的父子从属结构，应检查是否以层级型为主；若各单元需要依次执行，则不符合“无强制顺序”。

## B 统计图形与计算方式

| 表达任务 | 图形与数据处理 |
| --- | --- |
| 展示一组独立名称、符号、概念 | 图文索引、并列卡片、符号表；统一字段和版式模板，不必有数值统计 |
| 比较同构对象的一项数值 | 条形图、点图、单位图等；同一字段使用同一单位／标尺，可排序但排序不是数据的不可逆主干 |
| 展示多个独立对象的多个指标 | 矩阵图、小多图等；各对象保持相同字段和口径 |
| 展示独立关键词及其权重 | 词云或标签云；若有词频数据，可按频数／权重映射字号，否则仅作文字形态表达 |

数值计算取决于实际字段（计数、占比或均值等）；**“字母表型”规定的是数据关系，而不是必须采用的统计图形。** 不应把装饰性的字母大小、三角形面积或图片大小默认当作数值。

## C 视觉编码

点和重复符号区分各对象；线、格网或留白区分单元；同规格面／卡片承载相同字段。颜色可编码对象类别，长度／高度可编码明确数值，字号可以承担标题或可验证的权重编码。若采用立体形态或特殊造型，应注明哪些视觉量是装饰而非统计指标。

**核心：单元形式统一，数值尺度一致，允许从任意对象进入阅读，而非由一条强制路径贯穿所有单元。**

## D 数据与信息架构

最小 Excel 结构是一张**扁平表格**：**一个独立对象一行，各行具有相同列字段**。

| 对象ID | 对象名称 | 类别（可选） | 指标值（可选） |
| --- | --- | --- | --- |
| A | 对象甲 | 类别1 | 80 |
| B | 对象乙 | 类别2 | 60 |
| C | 对象丙 | 类别1 | 90 |

类别可以作为属性辅助上色或筛选，**不能单凭有类别列，就认定表格是层级型或编目型**。传统字母／符号索引可以另加索引键；多指标时各对象保持相同列名和单位。

## E 视觉叙事架构

**整体概览 → 可独立浏览的平行对象 → 对照共同字段 → 关注极值或代表性条目。** 读者既可从任一单元开始，也可按名称／数值浏览，阅读顺序不改变对象之间的底层关系。

**与其他逻辑区别：** 编年型重不可逆先后；层级型重父子归属；编目型同时具有不可逆阶段主干和下属层级；地理图型重空间关系；字母表型重独立同构、无强制序列。17种常用图形中的“视觉简历型”“单一图表型”“词云图”等均是**表现形式**，不能直接决定五大逻辑归类。

## 补充：独立同构数值单元（案例：Calling the Shots）

本仓库将字母表型作为**无强制顺序、无上下级关系、可独立查阅的同构单元**来辨识。除了传统字母索引和符号目录，还可以是多个国家、产品等实体按相同字段组成的扁平数据集合。此处“字母表型”描述的是数据单元的组织关系，**不要求画面一定出现A–Z字母排序**。与前文的字母索引用法相比，这是以数据结构为依据的扩展判断。

### A 基本数据逻辑
- **独立、平行、同构、可重排**：每个对象是独立记录，各记录字段相同，无父子关系或必须遵循的事件次序。
- 数值差异不会产生层级；可以按大小重排，也可以按分类浏览。
- 地区、题材等“类别属性”不等于以类别为父节点形成的层级主干。

### B 统计图形与计算方式
- 当各对象共享同一数量字段时，可采用 RAWGraphs 的 **Bar chart（柱状图）**以高度编码数量。
- 例如 `疫苗订购比例（%）=订购剂次数量÷国家人口×100%`。统一百分比尺度，使多个国家的数据可以读数与比较。
- 可以将矩形柱视觉变形为三角形，但宽度、面积和遮挡若无独立映射规则，不应被读作其他统计变量。

### C 视觉编码
- **点**：数据标记或三角形峰顶定位数值；**线**：轮廓和参考线；**面**：重复一致的单元形状。
- **体**：重叠制造纵深，但不自动表示第三维；**符号**：统一图形表示同构对象。
- **色彩**：对区域或类别编码；**高度**：对定量指标编码；**文字**：直接提供对象名称和数值。
- 图形统一、尺度一致、可跳读，是这类多对象数值可视化的重要形式特点。

### D 数据／信息架构
- 扁平表格：`对象ID｜对象名称｜类别｜统一量化指标`，一个对象一行；字段一致、各行平行。
- 呈现方式：`主题 → 多个独立对象 → 各对象的统一指标`；可附图例和基准线，但不构成父子数据结构。

### E 视觉叙事架构
- **非线性浏览**：从总体分布进入任意独立对象，读者不需遵守严格阅读顺序。
- **极值引导 → 整体分布 → 单项查阅 → 类别辨认**：用极值和统一量尺突出数量差异。
- **区分两种分类体系**：字母表型是五大数据逻辑之一；采用统一峰形或柱状图展示多国指标，可以在17种表现类型中属于**10-单一图表型信息图形**，而非必然属于“比较型”。

## 补充：独立关键词与造型词云（案例：灯塔 Lighthouse Word Cloud）

此案例延续本仓库对字母表型的**扩展判断**：当最小信息单元是彼此平行、可独立查阅、没有强制先后或父子关系的词语时，其底层是扁平独立单元集合。**这不意味着词云实际按 A–Z 排序；严格的字母索引图仍以字符作为检索键。**应把“五大数据架构逻辑”与“17种常见图形的视觉形式”分别判断。

### A 基本数据逻辑
- 关键词是最小单位：如 LIGHT、GUIDE、HOPE、NAVIGATION、SEA、FOUNDATION，独立、平行、同构、可重新安排。
- 多个词语通过共同主题产生**语义关联**，不是依靠事件时间、父子层级或空间坐标建立关系。
- **视觉上的主次或从上到下的塔身结构，不自动等于数据层级**；字母表型在这里取“无强制顺序、无层级的同构集合”这一扩展含义。

### B 统计图形与计算方式
- 常用类型为**词云图信息图形（Word Cloud）**，具体是具象轮廓式词云。可参照 RAWGraphs 的**自定义 Tag Cloud 图表**进行“词语＋数值权重→字体大小／色彩”的映射；它不是必须预装的原生图表，灯塔造型需要进一步定制布局。
- 词云若有源文本，可先计数词频 nᵢ，再计算相对词频 fᵢ＝nᵢ／Σnⱼ，进而映射字号；也可以事先人为设定重要度。
- **此原图没有公开频次或权重说明**；字号是视觉事实，不能把大小直接当作已验证的词频统计。LIGHT 多次出现也可能是装饰性重复。

### C 视觉编码
- **点**：未承载独立数据；**线**：放射状字列及曲线构成光束和平台轮廓；**面**：由密集字形拼成灯塔与岩石；**体**：弧形排版暗示空间感，不编码数值。
- **符号**：灯塔整体形象象征引导与希望；**色彩**：黑白对比突出轮廓，不提供数据分类；**字体**：粗体大写、手写字形、大小与旋转方向混排，使文字兼具内容与图形属性。
- 核心规则：**文字单元 → 字号／字重／方向／位置／密度 → 主题造型**。只有权重数据与映射关系明确时，才能解释为定量视觉编码。

### D 数据／信息架构
- Excel 基础结构：**一行一个关键词**，可记录“关键词｜语义类别｜权重（可选）｜布局区域”。
- 如 LIGHT／光亮／待定／两侧光束，HOPE／希望／待定／塔身，SEA／环境／待定／塔身下部。类别和布局区域属于附加属性，不是严格数据父节点。
- 信息组织：**主题灯塔 → 平行关键词集合 → 外形排布区域**；最后一步属于视觉设计，而非数据自身的层级结构。

### E 视觉叙事架构
- **先看整体轮廓 → 识别 LIGHT 等关键词 → 解读 GUIDE／HOPE 的象征 → 由 SEA／STORMS／FOUNDATION 延伸至航海环境与稳固根基**。
- 视觉阅读可以从任何词开始，路径非线性；塔身的上下排列只是引导视觉浏览，并不建立不可逆序列。

**对应案例**：[17-词云图信息图形｜案例1分析《灯塔造型词云》](../02-信息图形类型案例/17-词云图信息图形/案例1分析.md)

**区别提醒**：本案例的五大数据逻辑为**字母表型（扩展扁平独立单元）**，17种常用表现类型为**词云图信息图形**；“字体有大小”和“整体像灯塔”都不能据此改判成数据层级型，也不能假定存在未经证实的统计量。


## 补充：视觉简历的局部并列单元与字母表型的识别边界（案例：Garin Fajar）

> **分类定位**：常用图形种类为**13-视觉简历型信息图形**；就**整张图的五大数据架构逻辑**而言，不能仅凭“同一人物 → 教育／经历／联系方式／技能等资料类别”判为编目型；由于缺少贯穿全图的不可逆阶段主干，应按独立同构单元与真实父子结构重新核对。本节收入字母表型定义，是为了补充“**局部独立、同构、可重排**”与“**整图不同字段的资料分组**”之间的判断边界，**不依据单个技能模块就武断认定整张图均为字母表型**。

### A｜基本数据逻辑

- 个人肖像、介绍、学历、实习、职业能力、联系信息、软件能力与语言能力归属同一人，资料**按类别组织**，类别之间可以调整阅读顺序；这里的“分类”不是本仓库五大逻辑中“编目型”的充分条件。
- 软件能力模块的“软件 Logo＋七个圆点”具有**相同结构的横向条目**；各软件可独立查阅和重排，因此这一子模块具有局部字母表型（扩展含义）的特点。
- **判别要点**：“能够跳读／可重排”是线索，但**不是充分条件**；字母表型需以独立、平行、同构的对象为比较单位。教育、电话、实习等异构字段不足以直接证明全图是同构对象集合；同样，没有不可逆有序主干，不能判为编目型。

### B｜统计图形与计算方式

- 软件能力采用设计化的**点阵评分（Dot Rating）**：每行七个圆点；可借用 RAWGraphs **Matrix plot（矩阵图）** 的规则行列布局，再定制图标与色彩。**原图缺少完整图例**，不可直接从深浅点数推算实际熟练度。
- 语言能力采用 **Bahasa 100%、English 40%** 的百分比数字标注；圆形背景没有按数值比例分割，不能称为饼图或环形图。
- 仅在评分定义明确时，才可使用 `有效点数 ÷ 总点数 × 100%` 换算评价比例；原图中的装饰圆点不参与统计。

### C｜视觉编码

- **点**：技能栏的重复圆点为定性／等级编码，其他橙色波点为装饰；**线**：人物白描边、虚线分隔与字形轮廓；**面**：酒红、奶油、橙黄色块分区。
- **体**：人物后方错位色块营造纵深，但不表示三维统计；**符号**：教育、联系方式、职业与软件 Logo 作为类型索引；**色彩与字体**：暖色高对比、粗斜体、空心字叠压组织视觉重心。
- 应区分**数据编码**（技能点阵）和**版式装饰**（背景圆点、投影、色块面积）。

### D｜数据与信息架构

- 主表：`人物ID｜姓名｜简介｜联系方式`，一人一行。
- 归档表：`人物ID｜资料类别｜条目名称｜补充描述｜年份`，一类可有多个异构条目。
- 评分子表：`人物ID｜技能名｜评分位置／数值｜评价口径`，一个技能一行；此子表适合独立、同构、可重排的字母表型判断。
- **整页可整理为**“人物 → 资料类别 → 条目”的内容结构；但这不自动证明有不可逆编年主干，也不等于“多个主体拥有相同字段”的扁平同构表。是否属于层级型，应核对这些类别与条目是否构成实际父子归属。

### E｜视觉叙事架构

- **人物吸引 → 身份介绍 → 资历与实践 → 职业能力 → 技能评价**。左上人物照片是入口，右上介绍建立背景，中下条目可自由跳读，右下技能圆点和语言百分比形成能力焦点。
- 视觉阅读虽有导向，却不形成严格不可逆的编年顺序；**视觉层次的存在也不意味着数据存在层级父子关系**。
